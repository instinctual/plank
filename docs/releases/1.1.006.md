# 1.1.006 microphone queue recovery

The Mac Host discards decoded microphone PCM that has waited 100 ms in its
producer queue. A scheduler stall or a partial packet left after starvation
can no longer cause that queued speech to play when fresh audio arrives.
Expiry re-primes with fresh audio, and mute clears the queue.

Clock correction now uses smoothed queue occupancy and preserves a reserve
after consuming each output block. This prevents batched input from cancelling
the correction and causing periodic starvation with a slightly slower source
clock. Stereo channels retain the same timing and interpolation.

This is a Host-only behavior change. Kymux transport, microphone feature2,
stereo Opus framing and the 48 kHz virtual input ABI are unchanged. Existing
stereo-capable Clients remain compatible. The queue age limit is local to the
Host PCM queue; it is not an end-to-end latency or camera/microphone sync claim.
