# PLANK 1.4.18

Changes since [1.4.16](https://github.com/instinctual/plank/releases/tag/v1.4.16).

## Host

- Wake the macOS display before setting the remote desktop resolution.
- Keep the display awake during an active remote session and release that protection when the session ends.
- Recover from display sleep and interrupted first-time resolution setup without restarting the desktop.

The Host waits for the display to become drawable before changing its modes.
After wake, it briefly retries the same virtual-display identity if macOS has
not yet cleared an old registration. Existing power preferences, screen-lock
security, workstation identity and settings are preserved.

## Client

- Include these release notes in the version dialog. Client runtime behavior is unchanged.

Linux Host runtime behavior is unchanged. Metrics remain disabled by default
on macOS Host and Client.

## Validation

The signed Host candidate passed 37 display-recovery scenarios, nine
physical/headless readiness cases, and 26 real-QUIC session lifecycle cases
using synthetic capture and substituted power calls. These cover delayed wake,
mode changes, canceled setup, failed assertions and cleanup before capture drain.
Signing, notarization, stapling and Gatekeeper verification passed.

The exact candidate was installed on the affected macOS 27.2 machine. PLANK's
services restarted, the control endpoint returned HTTP 200, and the logs showed
successful resolution preparation. The desktop, WindowServer, configuration,
machine keys and boot time were preserved. A later observation found the
5120×2160 session running for more than ten minutes with PLANK's display-sleep
assertion active and no logged display or stream failure. Deliberately idle/sleep
recovery and new macOS 26.7 installed acceptance have not been recorded.

All four mainline packages were built on GitHub from
`cd8b6936f9215b69e18918a3161ba4300c0284ff` and passed their package gates.
Both Mac installers are signed, notarized, stapled and Gatekeeper-accepted.
Original manifests, source revisions and package checksums are verified.
Privacy, clipboard and Client compositor/input/launcher checks passed. Linux
transport passed three 900-frame loss tests at 150 Mbps with zero unrecovered
frames and zero proxy kernel drops.

An existing QUIC loopback test initially failed in the Linux Host and signed
Mac Host jobs: each frame was recovered exactly, but a zero-missing-source-symbol
assertion observed 45 and seven symbols respectively before FEC. One targeted
retry of each failed job passed with identical code, assertions and limits.
The independent mainline Mac Host job also passed. The cause of those initial
results remains unestablished; no tests were weakened. Transport code is unchanged,
and no new Mac transport-performance soak or mainline installation was performed.

The four installers, source manifest and checksums are published in
