# 1.0.154 candidate — RaptorQ upgrade and transport hardening

Branch: `raptorq-upgrade`. This is a test candidate, not a mainline release.

**Install matching Host and Client builds together.** RaptorQ 2 uses different
repair-symbol numbering. Native QUIC now negotiates `plank-native/2` and rejects
older peers before authentication or media; no compatibility decoder is shipped.

## Client

- Upgrade RaptorQ to 2.0.1 and reject malformed or oversized incoming messages.
- Cancel startup promptly, including during connection and authentication waits.
- Prevent missed shutdown wakeups in the render thread.
- Claim the correct queued video/audio/input item before copying it.
- Remove the Experimental label from macOS ScreenCaptureKit capture.

## Host

- Upgrade RaptorQ to 2.0.1 with bounded FEC parsing and decoder admission.
- Remove the disabled application datagram pacer and its build switches.
  Quinn scheduling and the existing 1 Gbps controller-budget floor remain;
  the encoder target, MTU, repair percentage and queue limits are unchanged.
- Bound reliable-data messages and queues; cancel pending transport setup.
- Linux: isolate blocking PAM work from shared authentication state, with
  operation deadlines and cancellation when the requesting client disconnects.

The candidate includes the preceding automatic Host-identity and virtual-primary
work. See the 1.0.152/1.0.153 notes and HANDOFF for those changes and acceptance.

## Validation

Local optimized transport tests pass for the Linux and source-first sender
selections. Final controlled-loss runs recovered all 5400 frames at 150 Mbps /
60 fps through 5% injected loss, with no unintended proxy drops. An earlier
failed run with proxy kernel drops remains documented, not erased by the repeat.
Fixed repair vectors, malformed-packet/budget checks, TLS version mismatch,
encrypted all-lane round trips, cancellation and C ABI tests pass.

Package results are recorded in HANDOFF and the artifact catalog when complete.
Native hardware playback, WAN, audio/input and login/logout acceptance remain
separate gates. Do not treat a Linux source-first test as macOS hardware testing.
