# 1.1.003 native-media investigation candidate

This feature candidate adds native camera forwarding from the Ubuntu Client to
the experimental macOS Host. Use matching Host and Client builds: authenticated
Mac launch schema6 rejects earlier peers. Camera capture starts off, including
reconnects. Select the camera in Client settings and enable it from the session
toolbar. Select PLANK Camera in the Host application after forwarding starts.

Camera H.264/MJPEG payloads are preserved through transport. The Mac camera
extension offers native compressed output and NV12, decoding only when required.
Actual application behavior, concurrent consumers, sustained loss/recovery,
unplug/reopen and audio/video synchronization require hardware qualification.
A format change or camera-off removes the stream; applications may need to
reopen it. No Client camera encoder or USB-device forwarding is introduced.

The microphone remains stereo Opus at 192 kbps constrained VBR with 10 ms
packets, and the Mac virtual input remains 48 kHz Float32 stereo. The source
queue now accepts one complete six-packet capture batch without avoidable
scheduling drops. Short direct camera/audio tests passed without microphone
gaps after this fix; that is not a sustained-performance or lip-sync result.

The signed Host now requires a Developer ID provisioning profile for
`la.instinctual.PLANK.Host` with system-extension installation permission.
The previous probe profile cannot authorize this app. Open PLANK Host and choose
Enable Camera, then approve the camera extension in System Settings. This
installs the virtual device; it does not start Client capture. Deactivation is
available through the installed Host's `--disable-camera` setup command; finish
that OS operation before uninstalling the containing Host app.

This document describes the candidate implementation. It does not assert
completed signing, installation, application acceptance, publication or release.
